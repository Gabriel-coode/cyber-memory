# Cyber Memory

Proyecto educativo de DAW desarrollado en pareja por Gabriel y Anthony. Juego Memory de conceptos de informática, con **Canvas 2D** como tablero principal y **Vue 3 + Pinia + Vue Router + D3** como arquitectura de aplicación y analítica.

## Estado real
**Infraestructura colaborativa inicial; no hay juego implementado todavía.** No marcar ningún bloque B00–B17 como completado sin PR integrado y pruebas. Las propuestas de funcionalidades son objetivos de diseño, no implementaciones verificadas.

## Empezar
1. Leer [docs/GDD.md](docs/GDD.md) y [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md).
2. Leer [AGENTS.md](AGENTS.md) y [docs/DECISIONS.md](docs/DECISIONS.md).
3. Consultar [Issues](https://github.com/Gabriel-coode/cyber-memory/issues); escoger solo tareas desbloqueadas.
4. Crear una rama corta por Issue: `feature/B00-entorno`, no ramas personales permanentes.
5. Abrir Pull Request, ejecutar pruebas, hacer revisión cruzada y Active Recall antes de integrar.

## Criterios de evaluación
Rúbrica de 48 puntos: HTML5 3, Canvas 18, Audio/Video 6, Drag & Drop 3, Storage + IndexedDB 6, Geolocation 3, File API 6 e History API 3. La puntuación no está garantizada por la sola presencia de la API. Ver [docs/RUBRIC.md](docs/RUBRIC.md).

## Colaboración con IA
ChatGPT y Gemini son tutores y revisores, no fuentes de verdad sobre el código. Para verificar progreso deben leer el repositorio, Issues y PR reales. El alumnado decide y comprende cada cambio. Ningún agente debe asumir que dispone de sincronización continua.

## Fuentes
Los documentos de partida fueron el GDD Cyber Memory v1.0, el plan de dependencias v1.0 y las rúbricas/ficha del profesor. Este repositorio contiene versiones Markdown operativas de esos diseños para que ambos asistentes puedan leerlas. El original Word sigue siendo un documento de referencia del equipo.
